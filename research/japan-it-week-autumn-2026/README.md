## Codexの最優先作業
1. **Codex Cloudの環境にGitHubリポジトリ `rensei11/01-event` を接続して実際にチェックアウトした状態から始める**。GitHub上にこのブランチを作るだけではCodexの実行環境にチェックアウトされない。環境設定・ネットワーク許可・ファイル保存能力を冒頭に確認する。
2. 前回Codexはブラウザで616件のカードを見て、同一詳細URLの重複7件を除いた609件を確認した。ただしブラウザの内容からCSVを保存できず失敗。**DNSエラーが出た同じターミナルからの再取得を繰り返さない**。
3. ブラウザで表示されたDOMまたは画面の公式データを、同じ実行環境のファイルへ書き出せるかをまず3件で試す。実行環境・ブラウザとファイルを繋げられなければ、新たな大量探索はせず正確にBLOCKEDを報告。
4. 成功した場合、会社名・小間番号・公式出展社詳細URLを**同じレコード**で全件取得。CSVはUTF-8 BOMまたはExcelで日本語を読める形式にする。表示順、ソース、ソースURLを記録する。個別の小間番号・ホールは絶対に推測しない。
5. 重複7件は同一URLなのか同一企業の共同出展なのかを正しく扱い、元の616行の生データと重複整理後の609件の両方の件数を説明する。公式名簿が別展示会を含むかも確認。
6. 数字を自然順に並べ替えた `exhibitors_sorted.csv` と `first_100.csv` を作成。ただし**小間番号順＝実際のホール配置順ではない**。ホールは公式で確認できた場合だけ別欄にする。
7. 成果物はこのディレクトリにのみ保存し、正常に作れたらこのブランチへcommit/push。main、`index.html`、`確認用.html`、イベントJSONは変更しない。
